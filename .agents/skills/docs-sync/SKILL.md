# 文档同步

1. 确定用户要求的主题或改动范围。审阅请求只报告；用户已要求修改时直接完成本地文档更新。不切分支、不覆盖现有工作。
2. 从当前源码、配置、路由、插件 SDK 和工程脚本建立事实清单。记录文件与符号；不能把设计目标写成已实现功能。
3. 对照已有文档检查路径、命令、参数、默认值、资源所有权、错误和清理行为。OpenAI 接口变化使用 `openai-knowledge` 核实版本。
4. 将用户说明放在根 README、模块 README、SDK README 或部署文档；将长期维护不变量放在 `.agents/references`。交叉链接，不重复整份实现说明。
5. 删除失效说明，同时修复引用者、CI 与示例。不生成业务客户端或手写 OpenAPI 副本。中文与英文文档按各自文件现有语言更新；本仓库没有上游的 MkDocs/翻译发布流程。
6. 静态检查本地链接、文件路径与示例字段。只有用户明确要求时才运行示例、测试、部署验收或模型调用。

用 [覆盖清单](references/doc-coverage-checklist.md) 做最后核对。报告已更新文件、依据和剩余验证缺口。
