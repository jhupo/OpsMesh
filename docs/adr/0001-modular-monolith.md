# ADR 0001：模块化单体与业务所有权

- 状态：采用，2026-10-30。
- 背景：平台包含Bot、用户、Agent、能力、运行、资源、记忆与观测；按技术层堆放全部service/model会模糊所有者。
- 决策：使用src布局，modules按业务职责划分，各自公开api/events并拥有internal仓储与表。bootstrap为组装例外；framework不依赖业务，infrastructure只提供技术设施。
- 结果：同一代码包可有多个进程入口，目录不等于微服务。跨模块通过DTO/标识和公开API协作。需要拆服务时保留同一公开语义，不提前建立分布式事务。
- 验证：静态导入检查+评审，关键跨模块流程通过集成测试验证。internal命名本身不形成语言层访问控制。
