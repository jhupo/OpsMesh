已结束的重构方案由正式架构文档接管，不保留另一份过期方案作为架构入口。

根目录 [AGENTS.md](../AGENTS.md) 规定完整设计、代码调查与文档维护要求。架构方案必须同时交代设计思想、职责依赖、文件树、端到端流程、接口数据、状态生命周期、异常恢复及实施验收，不能只设计其中一个点。

## 文档状态规则

- **当前实现**：给出源码入口；只描述源码可证实的能力。源码更新后重新核对。
- **目标方案**：给出目标文件树和完整流程，标注尚未实现的接口；关键问题未定时标记未闭合。
- **局部落地**：逐项说明已完成和待完成部分，不能笼统标成完成。
- **待迁移代码**：Cron、Execution、旧业务示例及 `tests/legacy/` 不属于当前发行；QQ、钉钉以各自独立插件文档为准。
- **调研资料**：记录来源与借鉴理由，不能以外部项目有某功能推断本项目也有。

新增或改动架构文档时同步本索引、相关方案的状态和相互引用。重构完成后更新正式架构、文件树和流程，迁出仍需保留的未完成事项，再删除被替代的旧重构文档并清理所有引用。具体收尾要求见 [AGENTS.md](../AGENTS.md#重构完成后的文档收尾)。
