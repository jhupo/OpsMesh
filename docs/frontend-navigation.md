# Dashboard 导航

本次修改把工作空间导航收敛为 8 组、平台管理导航收敛为 7 组。导航、命令搜索和资源页使用 `frontend/src/features/navigation/catalog.ts` 中的同一份目录。这里描述已接入的导航和查询页面，不代表每个后端操作都已经有完整的前端表单。

## 工作空间

| 一级菜单 | 二级菜单 |
| --- | --- |
| 工作台 | 总览、审批、通知 |
| Agent | Agent 列表、Agent 团队、会话、消息、模型接入 |

## 范围和权限

- 平台管理员通过头像菜单切换平台管理与工作空间；不再根据管理员身份把工作空间首页强制重定向。
- 工作空间切换后重新读取 `/workspaces/{id}/access/context`。菜单、命令搜索和资源页面根据 `allowed_actions` 过滤，页内运维查询也分别检查所需权限。后端仍负责最终授权和资源范围。
- Agent 团队与人员角色分开；成员、邀请和配额按空间权限展示。模型凭据归模型接入，MCP 凭据归 MCP。
- 会话先选择 Agent；平台调度诊断先选择工作空间；成果历史按任务和工作包查询；市场查询指定条目类型。
- 旧工作空间 runtime-spaces、automations、webhooks 地址重定向到新页面的对应查询选项；旧通知设置重定向到空间通知偏好。
- 新资源页面提供真实 API 查询、分页、详情、空态、加载和错误状态。审批与市场发布审核提供批准／拒绝确认，通知偏好可保存。原有任务、用户、工作空间管理及邮件表单继续复用。
- 账号邀请复用实际邀请表单；没有虚构邀请历史列表。基本配置、公告、预算、运行环境等新目录页面当前主要是查询入口，未在此次导航调整中补齐全部编辑、恢复、生命周期、授权和 Runtime 控制表单。
- 平台审计日志读取 `/admin/system/logs`，其内容是平台审计事件；平台队列页当前展示运维汇总。新导航不使用旧管理页的浏览器本地草稿作为后台事实。

## 验收

验证使用独立 PostgreSQL 数据库、真实 FastAPI 应用与 Vite 页面；Redis 采用测试替身，不连接生产环境。视觉证据和临时验收脚本保存在本地 `output/navigation-qa/`，不提交账号 Token 或临时数据库。

- **Implemented**：8 + 7 组菜单、共享目录、权限过滤、模式与空间切换、真实查询及上述操作。
- **Verified**：`pnpm typecheck`、`pnpm lint`（0 错误，5 条现有警告）、`pnpm build`（有大 chunk 提示）；65 个菜单地址遍历，60 个视口／主题页面检查均无页面崩溃或文档横向溢出；只读成员直接访问成员管理显示拒绝。空间审批批准和平台审核拒绝请求均返回 200，通知偏好切换后刷新仍保留。
- **截图检查**：1440 × 1000 桌面、390 × 844 移动，浅色／深色；15 组菜单的展开和当前项，桌面折叠菜单，移动抽屉，工作空间选择及切换后空态，头像模式菜单，命令搜索，数据表及详情弹窗，查询选择器，审批确认，邀请表单，通知偏好默认／保存后状态，查询加载／错误状态，邮件表单。证据在 `output/navigation-qa/screens/`。
- **Unverified**：生产部署、真实 SMTP 发送、外部版本源成功返回、真实 Worker／Runtime 操作与历史监控持续采集。版本源检查在本地返回 502；预算未配置时后端返回 404，页面展示错误。选择器目前读取前 100 个候选，不覆盖更大数据集的搜索体验。
