# 群聊收件箱、旧实现与框架边界清理

本次从 `modules/bots/conversations/queue.py` 出发，扫描全部源码的职责、导入、兼容分支和较长函数的完全重复实现，并重点追踪机器人接入、应用协调、持久化、备份和插件加载。扫描不能证明所有业务路径都没有缺陷；验证结果以本页记录为准。

## 持久化归属

原实现由群聊模块自行打开 SQLite 文件，包含建表、连接生命周期、事务锁和通用键值状态；这与平台已有的数据库、事务和版本化记录存储重复，还固定了 SQLite 与旧 `community_*` 表名。

现在删除该文件及路径式构造入口，不保留旧类名别名。应用接收 `ConversationInbox` 接口，bootstrap 使用同一个平台数据库提供命名空间收件箱。

| 路径 | 当前职责 |
| --- | --- |
| `modules/bots/conversations/api.py` | 消息、批次、收件箱及提供者合同；没有 SQL 或数据库依赖 |
| `modules/bots/internal/conversations/storage.py` | 私有表定义、作用域事务与 PostgreSQL 行锁；复用平台连接及事务生命周期 |
| `modules/bots/internal/conversations/inbox.py` | 消息去重、审核持久化、最近消息和活动记录 |
| `modules/bots/internal/conversations/batches.py` | 合批、单活动批次、Run/投递关联、恢复和保留策略 |
| `modules/bots/internal/conversations/state.py` | 在现有 VersionedRecordStore 上保存协调元数据，复用 CAS 与分页 |
| `infrastructure/coordination/process_lock.py` | 通用本机进程锁，供消费、重配置和离线备份使用 |
| `application/conversations` | 调用审核器、Agent、Bot 和知识服务；不建表、不持有独立数据库 |

平台数据库支持 SQLite/PostgreSQL。所有消息、批次和协调记录按项目命名空间隔离；索引使用定长摘要，支持较长的不透明厂商标识。去重保留第一次接收的内容，活动批次成员固定，处理中抵达的新消息进入下一批。Run ID、投递证据与待整理知识任务仍可恢复。

Outbox 负责可靠事件投递、租约、重试与死信；收件箱还保存审核、批次成员及 Run 关联，二者不能直接互换。它们复用数据库机制，保留各自状态机。审核消费者仍限定为本机单进程，由 OS 锁保护；本次没有增加分布式审核领取协议。

## 删除与保留

- 删除 OneBot 实现、默认注册、旧回调路径和协议专用测试，仅内置 QQ 官方 API 与钉钉。身份、路由、授权和幂等行为的相关测试迁到 QQ；第三方适配器注册测试保留。
- 删除旧 Bot 顶层配置的读取时迁移、`secrets:` 权限别名、知识库元数据的旧记录补建分支、Workspace 旧预留记录升级分支。
- 删除 `plugins/scheduler` 兼容导出以及空的内置插件命名空间。定时器位于 framework，持久任务属于 scheduling；外部插件继续通过 Loader 和 Depends 使用平台服务。
- 删除 Agent 字符串输出的兜底，群聊统一验证声明的 `respond` / `text` 输出合同；发送目标统一显式序列化投递序号。
- 删除独立队列文件备份分支。收件箱随主数据库备份；项目文件只备份已发布绑定。备份格式使用 `opsmesh.platform.v2`，不再缺省接受旧项目状态清单。
- 默认审核通知文案置空，有配置时才发送；示例文案和人物行为保留在 `examples/qq_community` 的配置、AGENTS.md 与上游 Skill。

框架扫描未发现 Jev、群聊角色或违规分类的业务提示词。Agent 的 instructions/prompt 字段、Matcher 的交互提示参数是通用扩展合同，继续保留。模型 API 能力检查、S3 协议支持、Python 支持版本处理和失败恢复属于有效功能，没有按“兼容”关键词机械删除。

383 个 Python 源文件的 AST 扫描未发现长度至少 12 行的完全相同函数体。此结果不代表不存在语义相近的功能；例如事件 Outbox、消息投递账本、群聊批次负责不同确认边界，不能合成一个状态对象。

静态检查增加了公开收件箱禁止导入 SQL/数据库实现，以及框架禁止导入示例应用的规则。完整职责清单和实际目录树已更新。

这是开发分支的结构调整，未推送、发布或替换服务器。已有安装必须先停止消费者并备份，运行 `opsmesh migrate` 安装新表；旧独立 SQLite 队列需要显式离线导入，不能通过新版入口直接恢复。没有在服务启动时加入旧表探测、双写、转换或兼容回退。旧备份须先使用对应旧版本恢复，再做离线升级，不能作为 v2 备份直接读入。
