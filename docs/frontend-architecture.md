# Frontend 架构

状态：完整上游基线上的 OpsMesh 登录、工作空间/项目选择与个人设置
更新：2026-09-22

## 基线与目录

使用 `satnaing/shadcn-admin` 的 `e16c87f` 源码及 PR #311 的 `95b8f5a` 国际化补丁。
按用户要求保留上游任务、聊天、应用、错误页及示例数据；这些演示数据不是 OpsMesh 业务记录。
采用 React、TypeScript、Vite、TanStack Router/Query、Tailwind 和 shadcn/ui。

`routes -> features -> api/components` 是依赖方向：薄路由负责入口，features 组合产品功能，
api 只消费公共接口，components/ui 保留上游原语。context 管理主题、布局及工作空间/项目选择；
i18n 管理中英双语，styles 保留上游语义主题。Shadcn Space 通过 components.json 注册表导入
源组件，不引入另一套运行时组件库。许可证保留在 frontend/licenses。

## 登录与外壳

未登录访问受保护路由跳转到 /sign-in，并保留站内 redirect。登录调用 /auth/login，成功后
加载 /auth/me，令牌仅存入标签页 sessionStorage。401 清除会话；退出撤销当前令牌。
label-06 承载 Email、Password 浮动标签、聚焦底线和错误红线；无注册、找回密码、第三方登录、
协议或解释段落。标签按要求固定为英文，按钮随中英语言切换。

外壳保留上游侧栏，底部用户信息与设置分组已移除。公共 AuthenticatedLayout 只挂载一个
Header，固定占据顶部区域，下面的内容容器独立滚动并随路由切换；页面不再创建标题栏。
Header 底部带分隔线，包含侧栏开关、分隔线、
All Projects、主题、语言、通知、消息及真实用户菜单。移除 Dashboard 顶部重复导航。
主题直接切换，语言仅中英。工作空间/项目选择及通知收件箱通过公共 API 加载；
其余模板演示不会据此变成已接入后端的产品功能。

整个设置区最大 1080px（含 176px 的标签导航），宽屏不铺满；资料面板最大约 880px，
所有设置标签共享约 880px 的内容面板，切换时不改变宽度或左边界。个人资料与密码、
通知范围与邮件通知分别在宽屏使用两列，小屏回到单列；通知选项按等高设置行排列，
不让开关和单选漂在大块空白中。资料表单只有一个保存按钮。
预留字段不能静默写 localStorage、模拟请求或
展示保存成功。后端支持后再补齐公开合同、加载与保存流程。

/auth/me 返回真实 platform_admin 布尔值。普通工作空间管理员不等于平台超级管理员；
前端不会按用户名或其他权限探测推断身份。Router 和 Query 调试面板仅挂在受保护布局内，
只有 DEV 且 platform_admin 为 true 且用户开启显示才加载；登录页绝不挂载。
本地存储仅保留每个用户的显示偏好，不作为授权依据。安装版 API 尚未包含该字段时保持隐藏，
需后续发布更新，不能描述为服务器已启用。

### 账户资料接口与扩展边界

`PATCH /auth/me` 接受 `display_name`、可选 `avatar_base64` 和可选 `password`
（`current_password`、`new_password`）。头像字段省略表示不修改，null 表示移除。
校验图片与密码后，姓名、头像、密码及令牌撤销在同一事务中提交。组合修改密码仍需
`password:change`，仅 `profile:write` 的令牌不能通过组合接口提升权限。
`PUT /auth/password` 保留为独立密码操作，共用同一密码校验和撤销实现。

`GET /auth/me` 增加 `avatar_version`；`GET /auth/me/avatar` 只读取当前用户头像，
不接受客户端指定其他用户 ID，响应为 WebP、private/no-store、nosniff。
用户资料属于全局身份域，不把它存入任意工作空间。迁移 `0103_user_avatars` 建立
按用户唯一的头像表，数据库限制每条图片不超过 256 KiB；用户表只保留内容哈希版本，
认证查询不加载二进制。替换/删除覆盖同一条记录，不产生对象存储孤儿文件。

图片使用 Pillow 12.3（支持 Python 3.11 的维护中图像库）完成解码、EXIF 方向校正和重编码；
拒绝 SVG、动画、超过 2 MiB 或边长超过 4096 的输入；最终最长边 256px，去掉来源元数据。
采用官方 [Image API](https://pillow.readthedocs.io/en/stable/reference/Image.html) 和
[ImageOps](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html)，不自写图片解析器。
没有选重型媒体框架或新建图片服务；已有工作空间 S3 文件模型要求租户归属，也不适合
全局账户的小型头像。后续若增加公开成员头像，必须单独定义成员可见性与缓存策略。

邮箱变更应有独立验证流程；通知偏好、会话管理、组织权限仍各自拥有独立合同，
不塞入资料更新请求。简介暂时禁用，不承诺尚未实现的存储。调试开关只是本设备显示偏好，
不能修改后端平台角色。

## 验证边界

只执行相关认证流程、前端 lint/typecheck/build，以及桌面/移动端浅深主题的实际渲染检查。
本次按用户要求暂缓新增后端接口联调、迁移实库验证和发布部署。已启动的一次本地流程检查
发现组合修改的权限拒绝未转换为 HTTP 403，已修正但未重跑；不能据此宣称新接口已完整验证。
安装版缺少 `avatar_version` 时，个人资料的新组合保存保持禁用；允许本地选择预览，但不会向
旧接口发送会被忽略的字段，也不会伪报保存成功。统一在后续新包安装并迁移后开启真实保存。
安装版联调使用本地 Vite 与 SSH 隧道，配置见 frontend/README.md；不在 VM 从源码编译部署。
模板统计、任务、聊天等页面仍为上游演示，不作为业务链路完成的证据。
