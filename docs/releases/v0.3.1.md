# OpsMesh v0.3.1

日期：2026-11-01。

本版增加独立 Linux 安装包，默认在本机安装应用并交给 systemd 管理。Docker Compose 是显式可选方式；不要求安装 Kubernetes，也不提供 Windows 服务安装。

## 发行制品

主要交付为 [opsmesh-0.3.1-linux.tar.gz](https://github.com/jhupo/OpsMesh/releases/download/v0.3.1/opsmesh-0.3.1-linux.tar.gz)，外部摘要文件为 [opsmesh-0.3.1-linux.tar.gz.sha256](https://github.com/jhupo/OpsMesh/releases/download/v0.3.1/opsmesh-0.3.1-linux.tar.gz.sha256)。另提供 [opsmesh-0.3.1-py3-none-any.whl](https://github.com/jhupo/OpsMesh/releases/download/v0.3.1/opsmesh-0.3.1-py3-none-any.whl)，供已有 Python 环境手动安装；它不包含 Linux 服务安装流程。完整附件见 [v0.3.1 发布页面](https://github.com/jhupo/OpsMesh/releases/tag/v0.3.1)。

安装包包含构建后的 OpsMesh wheel、带版本和哈希的 `requirements.lock`、安装脚本、systemd 单元、Compose/Dockerfile、`VERSION`、逐文件 `SHA256SUMS`、使用说明与许可证。包内没有 Python 解释器、`.venv`、第三方依赖 wheel 集合、开发源码仓库、测试、Git 元数据或开发配置。

wheel 是标准 Python 安装制品，其中包含应用模块；它不是独立机器码程序，也不承诺隐藏源码。源码仓库仍供开发者构建与测试使用，正式部署从 Linux 安装包执行。

## 默认本地安装

下载 Linux 安装包及对应摘要文件到同一目录后执行：

```sh
sha256sum --check opsmesh-0.3.1-linux.tar.gz.sha256
tar -xzf opsmesh-0.3.1-linux.tar.gz
cd opsmesh-0.3.1-linux
sha256sum --check SHA256SUMS
sudo bash install.sh
```

安装器优先复用服务用户可访问的本机 Python 3.11–3.14；没有适用解释器时，通过固定版本 uv 在线下载托管 Python 3.13。随后在目标机器创建独立虚拟环境，按哈希锁安装运行依赖，再安装包内 wheel。OpenAI Agents SDK 与 S3 依赖包含在运行依赖清单中。不会替换系统 Python，也不会把构建机器上的虚拟环境复制过去。

默认使用 SQLite，HTTP API 和后台协调器由一个 `opsmesh.service` 运行。应用以独立系统用户运行，配置位于 `/etc/opsmesh/opsmesh.env`，数据位于 `/var/lib/opsmesh`，版本制品位于 `/opt/opsmesh/releases/`，`/opt/opsmesh/current` 指向当前版本。

```sh
sudo systemctl status opsmesh.service --no-pager
sudo systemctl restart opsmesh.service
sudo journalctl -u opsmesh.service -f
curl --fail http://127.0.0.1:8000/ready
```

首次安装提示输入本地管理员密码。无人值守环境可通过 `--admin-password-stdin` 从密钥管理器提供一行密码，或使用已有受限文件 `--admin-password-file PATH`，两者互斥。密码只用于一次性初始化，不放入常驻服务配置。

安装完成后访问 `http://127.0.0.1:8000/docs` 登录并配置模型、Agent 和机器人。安装过程不调用真实模型，也不自动创建提供商凭据。

## 可选 Docker 安装

在同一安装包目录显式选择：

```sh
sudo bash install.sh --mode docker
```

Docker 模式用包内 wheel 和锁定依赖构建应用镜像，不复制整个源码仓库。Compose 管理 API、Worker、PostgreSQL 和 Redis；只发布 HTTP 端口，默认绑定 `127.0.0.1:8000`。应用容器以非 root 用户运行，数据库和文件数据保存在本实例的 volumes 中，不创建重复的原生 systemd 应用服务。

## 安装要求与升级

- Linux、Bash、root 权限与 GNU 常用命令；本地模式需要正在运行的 systemd、`curl`、Git 和 `runuser`。
- 本地 uv 固定为 `0.13.5`。自动下载安装适用于 glibc Linux 的 x86_64/aarch64 构建并核验摘要；其他架构须自行准备匹配版本及适用依赖。
- Docker 模式需要已安装并启动的 Docker Engine 和 Docker Compose v2。
- 两种模式均需要联网安装依赖；Docker 还需要拉取基础镜像。该安装包不能直接用于离线安装。

`--instance NAME --port PORT` 可安装独立实例。相同制品重复安装保留配置、数据和管理员身份；更换制品需要在备份后从新包目录运行 `sudo bash install.sh --upgrade`，Docker 实例同时保留 `--mode docker`。升级会停止应用写入进程、显式迁移并检查 schema，再启动新版本。`--no-start` 完成安装和初始化但不启动应用，本地单元仍启用开机启动。旧版本目录保留，数据库不会自动降级或回滚。

`--upgrade` 只用于已经由该安装器管理的实例。原 `v0.3.0` 手动部署不会被自动接管；其代码、配置和数据应先备份，再按原维护方式更新，或另建独立安装实例并执行经过核验的数据迁移。`0.2.x` 及更早架构依然没有自动迁移路径，兼容边界见 [v0.3.0 说明](https://github.com/jhupo/OpsMesh/blob/v0.3.0/docs/releases/v0.3.0.md)。历史 v0.3.0 标签和发布附件保持原样。

完整参数、已安装环境的维护 CLI、Compose 启停、配置和备份说明见 [Linux 安装指南](https://github.com/jhupo/OpsMesh/blob/v0.3.1/deploy/linux.md)与[运维说明](https://github.com/jhupo/OpsMesh/blob/v0.3.1/docs/operations.md)。不要通过删除数据库或 `docker compose down --volumes` 处理升级失败。

## 验证与限制

CI 从构建后的 Linux 安装包执行原生与 Docker 安装验收，覆盖首次安装、登录、重复安装、升级、重启、配置及管理员身份保留、服务用户权限和初始化凭据隔离。实际执行结果以[发布 PR](https://github.com/jhupo/OpsMesh/pull/90)及对应提交的检查为准，不把历史源码部署的验收当作本次制品验证。

本版不增加 Web UI、Claude Agent SDK 后端或 Windows 服务；外部机器人账号、多节点故障转移、离线分发及生产负载仍需各部署环境验收。应用安装模式与 Run/工具的执行隔离分别配置，本地安装本身不提供 OS 沙箱隔离。
