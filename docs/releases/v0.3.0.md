# OpsMesh v0.3.0

日期：2026-11-01。

本版本提供可运行的异步 Agent 与机器人平台，面向开发者试用。版本包通过 [GitHub Release](https://github.com/jhupo/OpsMesh/releases/tag/v0.3.0)分发。

## 与旧版本的兼容边界

`0.3.0` 替换了仓库原 `0.2.x` 及更早版本的实现架构。它不是对旧数据库进行原地升级的版本：

- 使用新的安装目录、独立数据库和数据目录，保留旧版本的代码、配置、数据库及文件备份。
- 旧配置文件需要按本版 `OPSMESH_*` 环境变量重新配置；新CLI不加载旧JSON/TOML平台配置。
- 旧数据库、审批检查点、Run状态和沙箱会话不能直接恢复为本版对象。`opsmesh migrate`只处理本架构登记的schema，不提供旧架构的自动转换。
- 旧插件、Agent适配器及HTTP客户端需要按本版公开合同适配。插件风格参考NoneBot2，不承诺兼容现有NoneBot插件或旧OpsMesh插件。
- 本版备份/恢复只面向本架构的备份格式，不应把旧备份目录当作新版恢复输入。

评估完成前保留旧部署作为回退环境。新旧部署不得共同写入同一数据库或工作目录。

## 本版能力

- 框架：Driver、Adapter/Bot、统一Event/Message、Matcher、上下文、嵌套Depends、插件元数据、加载/禁用及注册归属。
- 平台：本地账号与授权，Agent草稿/发布版本、Bot身份和Agent绑定、会话、持久调度、事件触发、通知、审批和运维入口。
- Agent运行：OpenAI Agents SDK后端、流式输出、工具和handoff/Agent-as-tool、护栏/钩子、审批恢复、模型历史与会话压缩。
- 能力与资源：代码工具、Skill/Git、脚本、MCP、知识检索、工作区、制品、快照、隔离执行及文件记忆。
- 机器人：钉钉Stream/OpenAPI、QQ官方Webhook/OpenAPI及OneBot兼容实现。
- 存储与观测：PostgreSQL/SQLite、事务Outbox、Redis协调、本地/S3内容存储、审计、日志、指标、OTLP/W3C追踪、用量和成本账本。
- 执行部署：进程内、Python子进程、Docker及逐Run Kubernetes Job，另有离线备份/验证/恢复命令。

目录边界同时收敛：`bootstrap`负责启动和组装，`application`承载跨模块运行流程；具体Run执行设施命名为`infrastructure/run_workers`；单一Embedding实现直接归入能力模块内部。框架抽象、机器人协议和平台账号/绑定分别归属`framework/adapters`、`infrastructure/bots`和`modules/bots`。

发布前修复了重复取消打断会话释放和资源清理的问题，并增加确定性回归；调度和SSE测试用受控时钟或事件同步验证并发。HTTP事件流在断连检测和重复取消期间保持取消语义，并等待订阅完成清理。PostgreSQL测试初始化文件仅写入SCRAM验证值，不存储明文连接密码。本机运行不要求Kubernetes。

## 安装发行包

需要Python 3.11+。创建并激活新的虚拟环境后执行：

```sh
python -m pip install "opsmesh[openai] @ https://github.com/jhupo/OpsMesh/releases/download/v0.3.0/opsmesh-0.3.0-py3-none-any.whl"
opsmesh --version
opsmesh init
opsmesh check
opsmesh serve
```

`init`要求在新数据库中设置本地管理员密码。默认工作目录下使用SQLite和`.opsmesh/`，也可通过`OPSMESH_DATABASE_URL`、`OPSMESH_DATA_DIRECTORY`指向本次部署专用位置。访问`http://127.0.0.1:8000/docs`使用HTTP API。

`openai`是可选依赖：需要该SDK后端时安装，核心框架可单独安装。S3存储另需`s3` extra，例如`[openai,s3]`。下载的本地wheel也可通过`python -m pip install "./opsmesh-0.3.0-py3-none-any.whl[openai]"`安装。以上方式不依赖PyPI发布。

源码安装使用本版源码包和uv 0.13.5，执行`uv sync --locked --dev --extra openai`。部署镜像示例中的`opsmesh:0.3.0`是本地构建/自有镜像仓库的示例标签，不表示存在公开容器镜像。

## 验证与限制

发布提交的CI执行和发布附件是该版本的验证入口；历史实施文档保留各自验证时点，不能代替本次提交的检查。默认测试采用受控模型，真实模型与外部服务测试显式启用。源码中的CI矩阵定义本身不表示所有组合已经执行成功。

- Web门户/控制台仅保留目录，Claude Agent SDK后端尚未实现。
- 钉钉和QQ具备协议实现与受控协议测试；真实外部机器人账号仍需部署联调验收。
- 多节点故障转移、跨物理主机恢复和长期压力负载尚未完成生产验收。
- 旧版本数据与新版本数据没有自动迁移路径；新部署应重新创建账号、模型、Agent及资源配置。
- Python同进程插件是受信代码，隔离要求由实际执行环境提供。外部副作用、模型请求与通知发送按各自幂等边界处理，不承诺外部动作恰好执行一次。

完整实现与限制见[SDK覆盖表](../design/sdk-coverage.md)、[机器人接入](../design/bot-adapters.md)、[运维说明](../operations.md)和[源码职责](../design/source-layout.md)。
