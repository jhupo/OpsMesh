# OpsMesh 0.1.0

首个正式版本交付 Agent 执行与编排后端、插件开发 SDK 和独立运维 CLI。
正式安装使用预构建 Docker 镜像或包含运行时的本机二进制包，不使用源码部署。

## 功能范围

- 发布 Agent/Provider 配置，创建持久 Agent/SandboxAgent、Session 和环境。
- Temporal 编排、事务 Outbox、审批、信号、取消和外部效果对账。
- 插件注册、ZIP 打包安装、工具/MCP/Skill/Hook/通道适配与热更新。
- 用户所有权、授权、额度、审计、加密、预算、模型用量和重试配置。
- 运行事件、定时任务、签名 Webhook、评测实验和用户反馈。
- 自研 QQ/钉钉网关，以及独立 API/Worker/Gateway 进程。
- 不可变发行目录、固定镜像摘要、数据库迁移、协调备份和恢复。

## 下载与平台

在 [v0.1.0 发布页](https://github.com/jhupo/OpsMesh/releases/tag/v0.1.0)下载：

| 资产 | 用途 |
| --- | --- |
| `install.sh` | Debian/Ubuntu amd64 安装入口 |
| `opsmesh-server-v0.1.0-linux-amd64.tar.gz` | 包含运行时及迁移资产的本机服务端 |
| `opsmesh-cli-v0.1.0-<platform>.tar.gz` / `.zip` | 原生运维 CLI，Linux/Windows/macOS 支持矩阵见发行格式 |
| `release-manifest.json`、`checksums.txt` | 包身份、镜像 digest、版本和摘要 |
| Python wheels / sdists | 插件开发及工程使用，不是第三种生产部署方式 |

API、Worker、Runtime 镜像由发行清单固定 digest。GitHub 自动生成的 Source code
压缩包不是部署资产。发行的原生 CLI 与服务端均不需要系统 Python、pip 或 uv。

## 升级注意事项

该版本重构了早期 RC 的执行实例、编排和网关接口。RC 用户应先备份并在隔离环境演练，
不能依赖旧接口或插件兼容别名。历史数据库迁移保留，目标为 `0005_platform_management`；
不自动将旧执行或编排历史转换为新实例，旧 Temporal Workflow 必须在切换 Worker 前处理。

迁移 `0004_native_gateway` 禁用旧通道配置并保留数据；需重新配置凭据、身份绑定和路由。
迁移后的数据库不能仅靠切换旧二进制回退；应按已验证快照协调恢复。
具体操作见[升级与恢复](https://github.com/jhupo/OpsMesh/blob/v0.1.0/deploy/server/delivery-operations.md)。

## 边界与限制

- 无内置前端、企业 SSO、组织管理、知识库或插件市场。
- 本机服务端仅支持 Linux amd64；桌面运维 CLI 不提供本地服务端。
- Docker 沙箱不支持跨独立 daemon 的自动故障转移，不提供沙箱磁盘总量额度。
- MCP 没有通用外部写入幂等保证；结果不确定时进入人工对账，不能盲目重试。
- QQ/钉钉真实消息收发依赖用户自己的平台凭据和测试会话；不将协议检查当作真实收发验收。

构建和发布检查范围见[测试说明](https://github.com/jhupo/OpsMesh/blob/v0.1.0/tests/README.md)及[发行格式](https://github.com/jhupo/OpsMesh/blob/v0.1.0/deploy/DISTRIBUTIONS.md)。
