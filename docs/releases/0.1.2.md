# OpsMesh 0.1.2

此版本修复消息处理的架构边界、群身份与调度问题。服务端、插件 SDK 和运维 CLI
统一为 0.1.2。部署继续使用预构建 Docker 镜像或包含运行时的本机二进制目录包。

## 主要变化

- message_filter 是独立插件扩展，每条原文审核后才激活和合批。审核异常有界重试，
  耗尽后阻断；撤回只针对被拒绝的原文，仍检查群授权与厂商权限。
- 移除网关历史查询与 bootstrap 提示词拼接，原生 Agents SDK Session 负责记忆。
  同群、同平台账号、同目标实例默认共享 Session；私聊继续按身份隔离。
- 显式共享群路由绑定受限平台账号和 Agent/Workflow，成员无需逐个注册。
  群角色作为事实逐条传递，不能替代平台或工具授权。
- 每条消息独立调度；滑动静默窗口、最长等待、条数、字节上限和 FIFO 有界。
  Agent 运行中到达的新消息进入下一批，恢复不会丢失各条发送者。
- Jev 仅在可选插件中审核内容。Agent 配置决定名字触发、接续回复或保持安静；
  单 Agent 不需要额外业务 Workflow。
- 保留原生模型重试，对过长 5xx Retry-After 提供显式 backoff 选项，默认继续尊重服务端。

## 升级

1. 停止入口，排空 submitted 网关消息、旧 Agent Workflow、审批和未决外部效果。
2. 使用协调备份保存数据库、Temporal、Session 文件、插件和密钥，再演练升级。
3. 使用发行安装器迁移到 `0007_gateway_admission`，再更新 API、Worker、Gateway。
   存量 Temporal 历史未验证跨版本重放，不应直接热替换仍运行的 Workflow。
4. 旧 group.history_scope 迁移为 session_scope；历史条数/TTL/清理配置删除。
   旧原始收件、Session 文件及旧映射保留，新范围使用新 Session，避免自动混合旧用户历史。
5. TypeSafe 示例改为 message_filter 资源；移除旧 decision 工具和额外 Workflow 绑定，
   按示例重建插件及通道配置。程序与依赖更新需重启，日常插件配置仍自动重载。

迁移不能安全反向拆分共享 Session。回退需要恢复升级前的协调备份，不能直接降级数据库。
实例、沙箱与原生 Session 不因 Run 完成而删除。

## 发布与验证

tag 发布流水线先验证源码、数据库、真实 Temporal/Docker/模型、独立 wheel、原生归档和
托管安装，再公开 Release。安装资产和镜像 digest 见发行页的 release-manifest.json。
GitHub 自动生成的源码压缩包面向开发，不作为安装包。

本轮本地证据与限制见 [验收记录](../acceptance.md)。合成厂商事件不能证明 QQ/钉钉真实
收发已验收，HTTP mock 不能证明 Jev 经生产代理可用。框架修复发布不自动升级生产部署。
