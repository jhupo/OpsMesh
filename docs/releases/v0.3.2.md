# OpsMesh v0.3.2

日期：2026-11-01。

本版收拢平台和框架的职责边界，新增个人模型配置、加密凭据与在线更新入口，完善 QQ 会话批处理和审核后的知识/记忆采集，并修复 Run 和事件流反复全表扫描的问题。仍为供开发者试用的早期版本。

## 主要变化

- 平台和个人默认模型在 Agent 发布时解析并固定版本；支持用户自有 endpoint、加密版本凭据和显式撤销。
- HTTP 与 Python 入口复用 Agent、Bot 绑定、Skill、MCP、脚本工具、知识库等管理用例；Python 应用使用公开入口声明和发布资源。
- QQ 官方 WebSocket 接收、分群身份和消息媒体处理。审核与聊天独立消费；每群共享 Session，已审核积压按上下文预算合批，执行中的新消息进入下一批。
- 受审核会话只在审核通过及发送确认后采集知识/记忆；网关、提交和持久 Run 执行均拒绝同时开启 Agent 自动记忆。
- Run 和流事件增加事务内索引投影，SQL 过滤与有界分页；后台恢复及审批遍历使用稳定游标。
- 类型化执行服务、资源和状态；OpenAI 专用状态留在后端，沙箱生命周期按后端注入，子环境状态独立。
- 发布、执行资源、终态收尾、worker 所有权、审批、Outbox 投递与领域事件分工明确，内部应用用例显式注入依赖。
- 统一能力管理写入口，删除重复转发、OneBot、旧调度导出和账户/权限转换兼容路径；保留钉钉及 QQ 官方适配器。
- 增加在线检查、下载及校验发布包的 CLI/授权 HTTP 入口；安装升级在文件锁下复核目标版本。代码插件仍需部署及重启。
- 收件箱纳入平台数据库，备份包含模型凭据密钥及项目绑定，备份清单使用 v2。

## 安装制品

主要部署制品为 [opsmesh-0.3.2-linux.tar.gz](https://github.com/jhupo/OpsMesh/releases/download/v0.3.2/opsmesh-0.3.2-linux.tar.gz) 和对应的 [.sha256](https://github.com/jhupo/OpsMesh/releases/download/v0.3.2/opsmesh-0.3.2-linux.tar.gz.sha256)。另提供 [wheel](https://github.com/jhupo/OpsMesh/releases/download/v0.3.2/opsmesh-0.3.2-py3-none-any.whl) 与附件总校验文件 `SHA256SUMS`。

Linux 包包含 wheel、哈希锁定的依赖清单、安装脚本及部署配置，不携带 Python 解释器、虚拟环境或开发源码仓库。安装器检查并复用本机 Python，必要时在线获取解释器并安装依赖。默认本机 systemd，可显式选择 Docker，不要求 Kubernetes。

```sh
sha256sum --check opsmesh-0.3.2-linux.tar.gz.sha256
tar -xzf opsmesh-0.3.2-linux.tar.gz
cd opsmesh-0.3.2-linux
sha256sum --check SHA256SUMS
sudo bash install.sh
```

已有该安装器管理的实例在备份后使用 `sudo bash install.sh --upgrade`；Docker 实例同时指定 `--mode docker`。参数、配置和服务管理见 [Linux 安装指南](../../deploy/linux.md)。

## 升级与兼容边界

`runtime_runs`、`runtime_stream` 表从 schema v1 升到 v2。升级前停止所有旧 gateway、worker 和独立 Run worker 并备份数据库及文件；安装新包后执行 `opsmesh migrate`、`opsmesh check`，再恢复写入。新旧程序不得混合写入，旧版不维护新增投影。迁移保留记录、版本与时间戳，拒绝未知版本和漂移，详见[迁移 0002](../../migrations/0002-runtime-projections.md)。

内部服务字典、旧 sandbox provider 合同、SessionClaims 占用枚举和重复管理方法有调整，插件需同版本升级，不提供兼容别名。OneBot 账号和已删除的旧调度入口须改用当前实现。v1 备份清单不能直接用于新版恢复，保留旧工具和原备份用于旧版回退；新版备份包含凭据密钥，应按敏感数据保护。

原 0.2.x 及更早架构仍没有自动升级路径。回退新 schema 需恢复匹配的数据库备份和旧应用包，不能仅切换程序；安装失败不要删除数据库或 Docker volumes。历史标签和附件保持原样。

## 验证与范围

本轮功能代码全量离线回归为 999 passed、32 skipped；追加持久 Run 审核策略回归 1 passed。临时 PostgreSQL 10 passed，包含已有数据升级、事务和并发。Ruff、格式检查、mypy（404 个源文件）、仓库检查及构建通过。发布提交的跨版本、跨平台和 Linux 安装检查以对应 GitHub Actions 结果为准。

本版不增加 Web UI、Claude SDK 后端、Windows 服务或完整语音/视频服务。跳过的 Redis、S3、Docker、原生沙箱、真实模型和 Kubernetes 环境测试不能算作本轮重新验收；不宣称生产规模压测或多节点故障转移已完成。更多边界见[架构重构记录](../reviews/2026-11-01-architecture-refactor.md)与[QQ 助手设计](../design/qq-assistant.md)。
