QQ 适配器只使用腾讯官方 `qq-botpy==1.2.1`，通过官方 `botpy.Client` 接收 WebSocket 事件，通过官方 `botpy.api.BotAPI` 发送消息和调用固定原生操作。旧的 NoneBot 适配器来源文件、复制的协议模型、Webhook 入口和本地传输层已经删除；来源记录只保留 [SDK.md](../src/opsmesh/gateway/adapters/qq/SDK.md) 与 [SDK.json](../src/opsmesh/gateway/adapters/qq/SDK.json)。

当前网关保留宿主 `Adapter` 合同、事件标准化、消息参数校验、持久操作和钉钉独有的 session webhook。QQ 不提供本地 HTTP/Webhook 兼容入口，也不在宿主内重复实现官方 SDK 的认证、心跳、重连或协议对象。

本轮只执行了依赖锁定、源码静态检查和导入边界检查；没有执行测试或测试收集，没有启动服务、连接 QQ/钉钉、调用模型、构建发行包或发布。真实平台行为和完整消息投递仍需单独验收。

## 钉钉事件内容补全

钉钉消息按公共事件合同规范化 text、image、file、audio、video、link、mention 和 platform 片段；原生 payload、Stream frame headers 及 SDK 解析投影分别保留在事件 `data` 中。富文本、@用户、文件/音频/视频元数据、卡片、订阅和 Graph 回调不再只保留少量字段；`isAdmin` 不再映射为平台角色。静态检查覆盖 168 个 Python 文件，Ruff 格式与规则、mypy（149 个源文件）和 9 项导入合同均通过；未执行测试、服务启动、真实钉钉连接或 SDK 回调验收。

本节保留上一轮源码审查、静态检查与发行构建结果；该轮没有执行测试、测试收集、服务启动、平台连接、服务器验收或模型调用。
