## 1. 范围与目标

按 V4 16.2 新增 S6.5 行交付 `governance.costs`——S7 execution 的前置账本，
不越界实现执行核心：

- 定价版本：subject（model/tool）append-only 价目，新版本价新工作，已准入预留
  钉死其版本。
- 预算三态：无行 `unconfigured`（准入并显式记账，绝不静默无限）、`unlimited`
  （显式授权决定，记录决定人与时间）、`limited`（限额 + 周期 + 执行策略）。
- 预留账本：`reserved → settled/released/uncertain` 状态机；每次收费操作恒有
  定价版本与费用上界；`uncertain` 是持久化核对态，不授予重试许可。
- 释放矩阵：正常结算释放未用余量；有证据明确未执行整笔释放；取消确认只证明
  执行停止，已发生用量必须结算、未知费用保留待核对。
- 窗口语义：monthly 周期 UTC `YYYY-MM`；lazy roll（预算行锁内关旧窗开新窗）；
  跨周期未决预留归属原窗口，跨期结算写旧窗。
- 授权三分：定价发布=平台管理员；预算与用量查询=空间 owner/admin；平台管理员
  不自动取得租户数据权限。

未实施且明确不做（记入文末待关闭集成门槛）：预留/结算的生产者接线
（execution claim，S7）、真实模型调用与 Workflow 重试/取消恢复（S7）、
治理 budget 与容量的等待引用（S7）。

## 3. 关键合同与角色

- **三态是三个不同事实**：无行=未配置（准入且显式记账，budget_state 记录在预
  留行上）；unlimited 是显式记录的决定（decided_by/at）；limited 携带周期与
  执行策略。任何"无配置=无限"的合并都是缺陷（反向实证第 3 项）。
- **预留状态机与释放矩阵**：settle 全额记录实际费用（超过上界部分如实入账并
  单独成 field）、释放未用余量；release 仅受理"有证据明确未执行"；settled 不
  可 release、uncertain 不可 release/settle（只能 reconcile）；取消确认不构成
  释放证据，未知费用保留至 reconcile。
- **uncertain 是持久化核对态**：带证据落库；不授予重试许可——重试 Activity 必
  须先读状态并路由到核对，不得对未知操作再调模型（S7 接线时强制执行）。
- **reconcile 可执行合同**：`not_executed` 释放、`succeeded` 按作证用量结算
  （超额含在内）、`failed` 保持 uncertain 并更新证据；调用方声明其见到的预算
  revision，不匹配即 ConflictError；未配置预算不存在 revision。
- **窗口与修订**：monthly 按 UTC 月 lazy roll（预算行锁内关旧窗开新窗）；跨周
  期未决预留归属原窗口、跨期结算写旧窗行；period 切换（monthly→none）先关窗
  再清空；预算 revision 每次变更递增，更新必须声明所见版本，降限低于窗口持有
  总量拒绝。
- **授权三分**：定价=平台管理员（`require_platform_admin`）；预算/用量/预留=
  空间 owner/admin（`WorkspaceBudgetScopeAdmission` 委托
  `workspaces.members.access.space_role`）；平台管理员不因定价权限取得租户数据
  权限。governance 不导入 workspaces：决定主体经 bootstrap 注入。
- **幂等与重放**：reserve 同 operation_id 同输入重放同一行（存在性检查 + 保存
  点冲突重放双路径）；异内容冲突；settle 重放返回原记录、异用量冲突；预算更
  新 revision 乐观并发。

## 4. 事务与外部效果

- 三账本同一调用方事务：锁序 Session/Run→用户额度→空间容量→预算；进程内账本
  使用同一 PG Session，不自行 commit（组合测试以真实回滚验证零残留）。
- reserve 锁序：预算行锁（`with_for_update`）先行 → operation_id 存在性检查 →
  准入判定 → 保存点插入（唯一约束冲突只回滚该插入并重放已提交行）。
- 窗口滚动在预算行锁内完成：关旧窗（写 `cost_budget_windows` 快照）→ 开新窗
  → 新预留归属新窗；结算按预留自身 window_key 写当前窗或旧窗行。
- 全部写操作经 `append_platform_event` 落审计（发布/预算变更/预留/结算/释放/
  未知/核对/超限警告），审计 details 只含金额与标识，不含密钥。
- HTTP 路由经 `session_transaction` 提交；预留账本无写路由，生产者（S7）在
  execution claim 路径同事务调用。
